- **도착은 내비 도착 신호로만.** 기사가 "도착했어"라고 말해서 도착하는 장면은 찍지 않는다.

## 3. 촬영 전 수정 — 완료 (2026-11-15 20시대)

### 3-1. 음성 하드코딩 제거, 되묻기·확인 대답도 Gemini가 해석 ✅
- 사용자 지적: "AI 기반 음성이라고 Gemini를 넣었는데 하드코딩하면 안 된다. 코드도 제출한다."
- 한때 넣었던 하드코딩은 **모두 삭제**했다.
  - 앱: 확인 대답을 단어 목록으로 판정하던 코드
  - 서버: "이게→2, 세계→3" 오인식 보정표
- **되물은 질문의 대답** ("몇 개인가요?" → 기사 대답)
  - 서버가 질문과 지금까지의 초안을 Gemini에 함께 넘긴다(`note_ai.PendingTurn`).
  - 대답에서 말하지 않은 값은 초안 값을 쓴다(`service._merge_pending`).
- **확인 창에 대한 대답**
  - 앱이 `pending_kind: "confirm"`으로 보내면 서버가 Gemini로 yes, no, unclear 중 하나로 판단한다(`kind: confirm_answer`, 저장은 하지 않음).
  - 앱은 yes일 때만 저장한다. AI를 쓸 수 없으면 unclear를 돌려주고, 기사는 버튼으로 확인한다.
- API 계약(`docs/api-contract.md` 음성 해석 절)을 갱신했다.
- 실제 Gemini 확인 결과
  - "세계"→3개, "네에게"→4개
  - "응 그렇게 해", "맞아", "네 저장해"→yes / "아니 세 개야"→no / "그래서", "네 안녕하십니다"→unclear
  - "이게"는 AI도 판단하지 못해 다시 묻는다.
- 에뮬레이터 확인(맥 `say` → 호스트 마이크)
  - "빈 용기 두 개 회수했어 창고로 반납해"가 "갱년기 이게 회수했어 참고로 반납해"로 인식됐고, 앱은 "몇 개인가요?"라고 되물었다.
  - "세 개"가 "세계"로 인식됐고, 앱은 "빈 용기 3개 … 기록할까요?"라고 물었다.
  - "응 그렇게 해" → "저장했습니다". DB에 빈 용기 3개, 창고로 저장됐다. 확인 후 시험 기록은 지웠다.

### 3-2. 2번 장면 음성 겹침 ✅
17:36 촬영분의 기기 로그는 남아 있지 않아 직접 확인하지 못했고, 같은 현상을 재현해 고쳤다.
- **원인 ① 앱 자기 음성을 기사 말로 받음**
  - 상시 듣기 중 뒷문 경고 음성이 맥 스피커에서 맥 마이크로 다시 들어갔다. 에뮬레이터 마이크는 `aec:false`다.
  - **수정:** 앱 음성(`SpeechOutput.speaking`, 다른 화면의 안내 포함)이 나오는 동안 듣기를 멈추고, 끝나면 다시 듣는다.
- **원인 ② 되묻기 상태가 풀리지 않음**
  - "몇 개인가요?" 뒤로 들어오는 아무 소리나 그 대답으로 처리돼 "몇 개인가요?"가 반복됐다.
  - **수정:**
    - 되묻기·확인 창은 30초 동안 대답이 없으면 닫힌다(`QUESTION_TIMEOUT_MS`).
    - 창을 닫거나 취소하면 질문도 끝난다.
    - 되묻는 중 소음(ignore)이 들어와도 질문은 유지된다.
- **함께 바뀐 동작**
  - 답변, "저장했습니다", "취소했습니다"를 말한 뒤 3초 더 보여 주고 창을 닫는다(`ANSWER_HOLD_MS`).

- 음성 ON, `hostmicon`. 앱이 말을 마친 뒤 1~2초 쉬고 말한다.
1. "여기서 뭐 내려야 해?" → "현재 방문지 C … 박스 4개" 답변 → 창이 닫힌다.
2. "빈 용기 두 개 회수했어, 창고로 반납해" → 확인 창 "C에서 빈 용기 2개 회수, 창고 반납 예정으로 기록할까요?"
3. "응, 그렇게 해" → Gemini가 확인으로 판단 → "저장했습니다" → 3초 뒤 창이 닫힌다.
- 인식기가 숫자를 놓쳐 "몇 개인가요?"라고 되물으면 "두 개요" 또는 "세 개"라고 대답한다. Gemini가 질문 맥락으로 읽는다.
- 확인 창에 대답이 없으면 30초 뒤 창이 닫힌다.
- 회수는 **출발 후에만** 저장된다. 출발 전에는 409 `baseline_not_confirmed`.
- 다시 찍을 때는 앞 촬영분 회수를 지운다. 회수 삭제 API는 없어서 DB에서 지운다.
  `delete from cargo_units where pickup_id is not null; delete from trip_events where type='pickup_added'; delete from pickups;` (샘플 데이터 전용, DB 사용자 `loadmate`)
  - **`cargo_units`를 빼먹으면** 지운 회수품의 단위가 "실림"으로 남아 3D 적재 화면에 회수품 수가 틀리게 나온다(2026-11-15 9번 첫 촬영 폐기 원인).

### 8. 메모·내역 (기사 음성 없음)
1. 왼쪽 메뉴 `메모`에서 차량 노트와 방문지 메모 목록을 보여 준다.
2. `내역`에서 오늘 운행 기록을 보여 준다. 출발·도착·하차·이상·회수가 나오고, 각 기록의 출처(화면·음성·카메라)가 표시된다.
3. 정확한 조작 순서는 촬영 전에 화면을 보고 정한다.

### 9. 회수품 반납·운행 완료
1. C 도착 신호를 넣고, 하차를 완료한다(트렁크 열기·닫기).
2. 회수품(빈 용기 2, 창고)을 반납 처리한다. 앱 화면 버튼 또는 `POST /trips/{id}/pickups/{pid}/return`. 화면 위치는 촬영 전에 확인한다.
3. 남은 방문지·회수품이 없으면 반납 직후 서버가 운행을 자동 완료한다(`운행 종료` 버튼 없음). `운행` 메뉴에서 "운행 완료 · 남은 짐 박스 0"을 보여 준다.
